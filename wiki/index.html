1. Overview

1. Resumen

Robot Path Follower Tester is a browser sandbox for a 4-wheel differential-drive rover. Place waypoints, choose a planner, and watch it drive in 3D — no ROS, no Gazebo.

npm install
npm run dev      # http://localhost:5173/
npm run build
node scripts/smoke_sim.mjs

Core files stay portable: index.html, main.js, nav.js, style.css.

Robot Path Follower Tester es un sandbox en el navegador para un rover diferencial de 4 ruedas. Colocas waypoints, eliges un planificador y lo ves circular en 3D — sin ROS ni Gazebo.

npm install
npm run dev      # http://localhost:5173/
npm run build
node scripts/smoke_sim.mjs

El núcleo es portable: index.html, main.js, nav.js, style.css.

2. Algorithms

2. Algoritmos

Built-in modes live in nav.js. Pick one in the left panel (Bug2 is the default).

ModeIdWhat it does
Bug2 (M-line) bug2 Drives along the M-line toward the goal. When blocked, follows the obstacle boundary until it can leave back toward the goal.
Pure Pursuit pure_pursuit Steers toward a lookahead point on the path; shared safety can nudge around nearby obstacles.
VFH vfh Builds a local histogram of obstacle sectors and picks a clear steering valley toward the waypoint.
Custom (JS) custom Your loop() sets v and omega from live robot/sensor variables.

All modes share the same fused sensor reading and a safety / recovery layer (stuck detection, go-around).

Los modos van en nav.js. Se eligen en el panel izquierdo (Bug2 es el default).

ModoIdQué hace
Bug2 (M-line) bug2 Sigue la M-line hacia la meta. Si hay obstáculo, sigue el contorno hasta poder salir otra vez hacia la meta.
Pure Pursuit pure_pursuit Apunta a un punto de lookahead en la ruta; la capa de seguridad puede rodear obstáculos cercanos.
VFH vfh Arma un histograma local de sectores con obstáculos y elige un valle libre hacia el waypoint.
Custom (JS) custom Tu loop() asigna v y omega con variables del robot/sensores en vivo.

Todos comparten la misma lectura fusionada de sensores y una capa de seguridad / recuperación (atasco, rodeo).

3. How the software works

3. Cómo funciona el software

UI layout

PanelRole
LeftSensors, algorithm, Start / Reset, Error Report, Move Objects
Center3D arena. Short click = waypoint. Orbit camera. Custom JS pad overlays here.
RightDrag props, save/load maps, draw terrain, prop weight/scale

Mission loop

  1. Place waypoints (rover pose = start).
  2. Enable sensors and pick an algorithm.
  3. Start Mission — each frame: read sensors → compute v/omega → applyMotion → terrain tilt / physics.
  4. A waypoint is passed when the rover is close enough (or footprint touches it with bumper/hit-test on).
  5. Unreachable waypoints after go-around attempts are skipped (purple).

Data flow

SensorSuite.read()  →  fused reading
computeNavCommand() →  { v, omega }
applyMotion()       →  yaw + XZ pose (kinematic)
applyRoverTerrain() →  height + pitch/roll from 4 wheels
cannon-es           →  props / cones the rover can push

Error Report packages robot state, map snapshot, attempts, and the recent log so you can paste it into chat.

Interfaz

PanelRol
IzquierdaSensores, algoritmo, Iniciar / Reset, Reporte de error, Mover objetos
CentroArena 3D. Click corto = waypoint. Órbita de cámara. El pad Custom JS se abre aquí.
DerechaArrastrar props, guardar/cargar mapas, dibujar terreno, peso/escala

Ciclo de misión

  1. Coloca waypoints (la pose del rover es el inicio).
  2. Activa sensores y elige algoritmo.
  3. Iniciar misión — cada frame: leer sensores → calcular v/omega → applyMotion → inclinación / física.
  4. Un waypoint se pasa si el rover está cerca (o el footprint lo toca con hit-test on).
  5. Si no se alcanza tras rodeos, se omite (morado).

Flujo de datos

SensorSuite.read()  →  lectura fusionada
computeNavCommand() →  { v, omega }
applyMotion()       →  yaw + pose XZ (cinemático)
applyRoverTerrain() →  altura + pitch/roll de 4 ruedas
cannon-es           →  props / conos que el rover empuja

Reporte de error junta estado del robot, mapa, intentos y el log reciente para pegarlo en el chat.

4. Sensors

4. Sensores

Toggle sensors independently. Algorithms only use what is active.

SensorRole
LIDAR360° scan (~6 m), corridor clearance for planning
UltrasonicFront cone (~4 m)
3× IRShort front contact (~0.6 m)
Floor IRDepression edges. Off = drive into holes like a 4×4; on = avoid
Spring bumperContact hit-test; blocks overlap when on

Terrain stamps (✏️): ↑ mountain / ↓ hole. Raised edges hit LIDAR/US/IR; holes are for Floor IR. The rover body tilts from the four wheel ground samples.

Activa sensores por separado. El algoritmo solo usa lo que esté encendido.

SensorRol
LIDAREscaneo 360° (~6 m), holgura de corredor para planear
UltrasónicoCono frontal (~4 m)
3× IRContacto corto frontal (~0.6 m)
IR de pisoBordes de hoyos. Off = entra como 4×4; on = evita
ParachoquesHit-test de contacto; bloquea solapes si está on

Sellos de terreno (✏️): ↑ colina / ↓ hoyo. Bordes elevados entran a LIDAR/US/IR; los hoyos son para IR de piso. El chasis se inclina según las 4 ruedas.

5. Your own algorithms (Custom JS)

5. Tus propios algoritmos (Custom JS)

  1. Select Custom (JS) — the pad opens over the 3D view.
  2. Copy the read-only void setup API and paste it to an AI or notes.
  3. Write a loop() that assigns v and omega.
  4. Check → Save (stored in localStorage.customLoopJs).

Variables you can read

robotX, robotZ, heading, waypointX, waypointZ, waypointDist, headingErr, blocked, forwardClear, nearest, lidar, ultrasonic, ir, floorIr, MAX_SPEED, MAX_OMEGA, plus whitelisted Math and draw(x, z).

v = MAX_SPEED * 0.60
omega = headingErr * 2.00
draw(robotX, robotZ)

Forbidden: DOM, fetch, eval, new, objects, function/return. Only robot vars, math, and draw.

Want a new built-in algorithm?

Add a mode in nav.js (command function + registration), then a radio/button in index.html and i18n strings in main.js. Keep the portable layout — avoid splitting into many micro-modules unless you need to.

Want a new sensor?

Extend sensorConfig + UI checkbox in main.js/index.html, implement the reading in SensorSuite (nav.js), and expose the value to Custom via the Custom setup text / loop wrapper in main.js.

  1. Elige Custom (JS) — se abre el pad sobre la vista 3D.
  2. Copia el API de void setup (solo lectura) y pégalo a una IA o a tus notas.
  3. Escribe un loop() que asigne v y omega.
  4. Checar → Guardar (queda en localStorage.customLoopJs).

Variables de lectura

robotX, robotZ, heading, waypointX, waypointZ, waypointDist, headingErr, blocked, forwardClear, nearest, lidar, ultrasonic, ir, floorIr, MAX_SPEED, MAX_OMEGA, más Math permitido y draw(x, z).

v = MAX_SPEED * 0.60
omega = headingErr * 2.00
draw(robotX, robotZ)

Prohibido: DOM, fetch, eval, new, objetos, function/return. Solo vars del robot, matemáticas y draw.

¿Quieres un algoritmo built-in nuevo?

Agrégalo en nav.js (función + registro), botón en index.html e i18n en main.js. Mantén el diseño portable — no lo partas en muchos micromódulos si no hace falta.

¿Quieres un sensor nuevo?

Extiende sensorConfig + checkbox en main.js/index.html, implementa la lectura en SensorSuite (nav.js) y expón el valor al Custom en el texto de setup / wrapper del loop en main.js.

7. FAQ

7. Preguntas frecuentes

Why doesn’t the rover avoid the hole? ¿Por qué el rover no evita el hoyo?

Floor IR defaults off so it can drive into depressions like a 4×4. Turn Floor IR on to treat hole edges as obstacles.

IR de piso viene apagado para que entre a depresiones como un 4×4. Actívalo para tratar los bordes del hoyo como obstáculos.

Does the rover tilt on uneven terrain? ¿El rover se inclina en terreno irregular?

Yes. Height is sampled under each of the four wheels; pitch/roll follow the averages (with suspension travel on the wheel meshes).

Sí. Se toma altura bajo cada una de las cuatro ruedas; pitch/roll siguen los promedios (con recorrido de suspensión visual).

Where did the side Log go? ¿Dónde quedó el Log del costado?

It lives inside Error Report (state + recent log + JSON/CSV export). Cleaner right panel.

Está dentro de Reporte de error (estado + log reciente + export JSON/CSV). Panel derecho más limpio.

How do I save / load a map? ¿Cómo guardo / cargo un mapa?

Save map stores a dated entry in the browser. Load map opens a picker with timestamps and counts (waypoints / props / terrain).

Guardar mapa guarda una entrada con fecha. Cargar mapa abre un selector con timestamps y conteos (waypoints / props / terreno).

Is this a full dynamics simulator? ¿Es un simulador de dinámica completo?

No. The rover is kinematic (applyMotion). cannon-es drives props/cones. Great for path/sensor ideas — not validated vehicle dynamics.

No. El rover es cinemático (applyMotion). cannon-es mueve props/conos. Ideal para ideas de ruta/sensores — no es dinámica vehicular validada.

Can I use Python algorithms? ¿Puedo usar algoritmos en Python?

Not in-browser today. Use Custom JS, or fork and bridge an external process. Python support is on the roadmap idea list.

Hoy no en el navegador. Usa Custom JS, o haz fork y conecta un proceso externo. Python está en la lista de ideas.
