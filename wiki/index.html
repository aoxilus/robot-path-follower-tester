1. Overview

1. Resumen

Robot Path Follower Tester is a browser sandbox for a 4-wheel differential-drive rover. Place waypoints, choose a planner, and watch it drive in 3D — no ROS, no Gazebo.

npm install
npm run dev      # http://localhost:5173/
npm run build
node scripts/smoke_sim.mjs

Core files stay portable: index.html, main.js, nav.js, style.css.

Robot Path Follower Tester es un sandbox en el navegador para un rover diferencial de 4 ruedas. Colocas waypoints, eliges un planificador y lo ves circular en 3D — sin ROS ni Gazebo.

npm install
npm run dev      # http://localhost:5173/
npm run build
node scripts/smoke_sim.mjs

El núcleo es portable: index.html, main.js, nav.js, style.css.

2. Algorithms

2. Algoritmos

Built-in modes live in nav.js. Pick one in the left panel (Bug2 is the default).

ModeIdWhat it does
Bug2 (M-line) bug2 Drives along the M-line toward the goal. When blocked, follows the obstacle boundary until it can leave back toward the goal.
Pure Pursuit pure_pursuit Steers toward a lookahead point on the path; shared safety can nudge around nearby obstacles.
VFH vfh Builds a local histogram of obstacle sectors and picks a clear steering valley toward the waypoint.
Custom (JS) custom Your loop() sets v and omega from live robot/sensor variables.

All modes share the same fused sensor reading and a safety / recovery layer (stuck detection, go-around).

Los modos van en nav.js. Se eligen en el panel izquierdo (Bug2 es el default).

ModoIdQué hace
Bug2 (M-line) bug2 Sigue la M-line hacia la meta. Si hay obstáculo, sigue el contorno hasta poder salir otra vez hacia la meta.
Pure Pursuit pure_pursuit Apunta a un punto de lookahead en la ruta; la capa de seguridad puede rodear obstáculos cercanos.
VFH vfh Arma un histograma local de sectores con obstáculos y elige un valle libre hacia el waypoint.
Custom (JS) custom Tu loop() asigna v y omega con variables del robot/sensores en vivo.

Todos comparten la misma lectura fusionada de sensores y una capa de seguridad / recuperación (atasco, rodeo).

3. How the software works

3. Cómo funciona el software

UI layout

PanelRole
LeftSensors, algorithm, Start / Reset, Error Report, Move Objects
Center3D arena. Short click = waypoint. Orbit camera. Custom JS pad overlays here.
RightDrag props, save/load maps, draw terrain, prop weight/scale

Mission loop

  1. Place waypoints (rover pose = start).
  2. Enable sensors and pick an algorithm.
  3. Start Mission — each frame: read sensors → compute v/omega → applyMotion → terrain tilt / physics.
  4. A waypoint is passed when the rover is close enough (or footprint touches it with bumper/hit-test on).
  5. Unreachable waypoints after go-around attempts are skipped (purple).

Data flow

SensorSuite.read()  →  fused reading
computeNavCommand() →  { v, omega }
applyMotion()       →  yaw + XZ pose (kinematic)
applyRoverTerrain() →  height + pitch/roll from 4 wheels
cannon-es           →  props / cones the rover can push

Error Report packages robot state, map snapshot, attempts, and the recent log so you can paste it into chat.

Interfaz

PanelRol
IzquierdaSensores, algoritmo, Iniciar / Reset, Reporte de error, Mover objetos
CentroArena 3D. Click corto = waypoint. Órbita de cámara. El pad Custom JS se abre aquí.
DerechaArrastrar props, guardar/cargar mapas, dibujar terreno, peso/escala

Ciclo de misión

  1. Coloca waypoints (la pose del rover es el inicio).
  2. Activa sensores y elige algoritmo.
  3. Iniciar misión — cada frame: leer sensores → calcular v/omega → applyMotion → inclinación / física.
  4. Un waypoint se pasa si el rover está cerca (o el footprint lo toca con hit-test on).
  5. Si no se alcanza tras rodeos, se omite (morado).

Flujo de datos

SensorSuite.read()  →  lectura fusionada
computeNavCommand() →  { v, omega }
applyMotion()       →  yaw + pose XZ (cinemático)
applyRoverTerrain() →  altura + pitch/roll de 4 ruedas
cannon-es           →  props / conos que el rover empuja

Reporte de error junta estado del robot, mapa, intentos y el log reciente para pegarlo en el chat.

4. Sensors — code & how they steer together

4. Sensores — código y cómo guían juntos

All sensing lives in nav.js → SensorSuite.read(). Each checkbox in the UI flips a flag in sensorConfig. A disabled sensor returns null and is ignored.

sensorConfig = { lidar, ultrasonic, ir, floorIr, hitTest }

each frame:
  reading = SensorSuite.read()
  cmd     = computeNavCommand(algo, waypoint, reading, …)
  applyMotion(cmd.v, cmd.omega)

Shared outputs (fused reading)

FieldMeaning
polar[36]360° clearance map (bin 0 = forward). LIDAR seeds it; US / IR / Floor IR write into nearby bins with Math.min.
forwardClearShortest distance in the front sector (±3 bins ≈ ±30°).
blocked1 if any enabled sensor votes for avoidance.
steerHint-1 / +1 = prefer left / right when the nose is tight.
minObstacleDistNearest hit from active channels.
lidar / ultrasonic / ir / floorIrRaw arrays for Custom JS and telemetry.

LIDAR (sensorConfig.lidar)

  • Code: 36 headings × castCorridor() — 5 parallel rays across the rover width so thin obstacles still register.
  • Range: LIDAR_RANGE (~6 m). Refresh every 0.18 s (cached between updates).
  • Targets: cones, props, raised terrain walls (not holes).
  • Vote: front sector < 1.80 m → avoidance.
for i in 0..35:
  angle = i/36 * 2π
  dists[i] = castCorridor(origin, worldDir(angle), LIDAR_RANGE, halfWidth)
out.polar = copy(dists)

Ultrasonic (sensorConfig.ultrasonic)

  • Code: 3 rays at −0.35, 0, +0.35 rad (front cone).
  • Range: ULTRASONIC_RANGE (4 m). Single ray each (no corridor).
  • Fuse: writes into polar bins near forward; if IR is off and center < 1 m, sets steerHint.
  • Vote: any of the 3 < 2.00 m.

3× IR front (sensorConfig.ir)

  • Code: rays from left / center / right of the bumper, along forward, range IR_RANGE (0.6 m).
  • Role: contact-zone “whiskers”. Can set blocked + steerHint early; also patches polar bins −2, 0, +2.
  • Vote: any IR < ~0.95 × range.

Floor IR (sensorConfig.floorIr) — default OFF

  • Code: same 3-angle pattern, but castTargets(..., floorTargets()) — only sunken terrain meshes.
  • Off: rover can drive into holes (4×4). Physics still tilts the chassis.
  • On: hole edges become obstacles → vote / blocked / polar fuse.
  • Vote: min reading < ~0.95 × FLOOR_IR_RANGE (3 m).

Spring bumper / hit-test (sensorConfig.hitTest)

  • Not a ray. Uses footprint AABB / queryPose in main.js.
  • On: motion refuses overlap; bumper compresses; waypoint can be “touched” by the hull.
  • Off: rover may push light props via cannon-es impulses.

How votes become “blocked”

lidarVote      = front LIDAR < 1.80 m
ultrasonicVote = any US < 2.00 m
irVote         = any IR near range limit
floorIrVote    = hole edge detected

sensorVotes = sum of votes
blocked     = sensorVotes >= 1   // ANY one sensor is enough

No sensor needs another’s permission. More sensors = better coverage, not a committee veto.

How that guides the robot

  1. computeNavCommand always sees the fused reading.
  2. Safety layer (safetyCommand / go-around): if the nose is choked, reverse / turn using steerHint and polar, then resume.
  3. Bug2 uses blocked + M-line leave; Pure Pursuit slows on low forwardClear; VFH picks the clearest polar sector; Custom reads whatever you use in loop().
  4. Stuck recovery: if pose barely moves ~1.5–1.8 s → reverse → look at clearest polar bin → escape.
read() → { polar, blocked, forwardClear, steerHint, … }
     ↓
safety / recovery? ──yes──→ override v, omega
     ↓ no
algo (bug2 | pure_pursuit | vfh | custom) → v, omega
     ↓
applyMotion → wheels + pose

LIDAR (sensorConfig.lidar)

  • Código: 36 rumbos × castCorridor() — 5 rayos paralelos a lo ancho del rover.
  • Alcance: LIDAR_RANGE (~6 m). Se refresca cada 0.18 s (cache).
  • Blancos: conos, props, paredes de terreno elevado (no hoyos).
  • Voto: sector frontal < 1.80 m → evitar.
for i in 0..35:
  angle = i/36 * 2π
  dists[i] = castCorridor(origin, worldDir(angle), LIDAR_RANGE, halfWidth)
out.polar = copy(dists)

Ultrasónico (sensorConfig.ultrasonic)

  • Código: 3 rayos a −0.35, 0, +0.35 rad (cono frontal).
  • Alcance: ULTRASONIC_RANGE (4 m). Un rayo por ángulo.
  • Fusión: escribe en bins polares del frente; si IR está off y el centro < 1 m, pone steerHint.
  • Voto: cualquiera de los 3 < 2.00 m.

3× IR frontal (sensorConfig.ir)

  • Código: rayos desde izquierda / centro / derecha del parachoques, hacia adelante, IR_RANGE (0.6 m).
  • Rol: “bigotes” de contacto. Pueden poner blocked + steerHint; también parchan polar −2, 0, +2.
  • Voto: cualquier IR < ~0.95 × alcance.

IR de piso (sensorConfig.floorIr) — default OFF

  • Código: mismos 3 ángulos, pero solo contra mallas de terreno hundido.
  • Off: el rover puede meterse al hoyo (4×4). La física igual inclina el chasis.
  • On: el borde del hoyo es obstáculo → voto / blocked / polar.
  • Voto: mínimo < ~0.95 × FLOOR_IR_RANGE (3 m).

Parachoques / hit-test (sensorConfig.hitTest)

  • No es un rayo. Usa la huella AABB / queryPose en main.js.
  • On: no atraviesa; el bumper se comprime; el hull puede “tocar” waypoints.
  • Off: puede empujar props ligeros con cannon-es.

Cómo los votos ponen blocked

lidarVote      = LIDAR frontal < 1.80 m
ultrasonicVote = algún US < 2.00 m
irVote         = algún IR cerca del límite
floorIrVote    = borde de hoyo detectado

sensorVotes = suma
blocked     = sensorVotes >= 1   // BASTA UN sensor

Ningún sensor necesita permiso de otro. Más sensores = mejor cobertura, no un veto por comité.

Cómo eso guía al robot

  1. computeNavCommand siempre recibe el reading fusionado.
  2. Capa de seguridad (safetyCommand / rodeo): si el hocico está tapado, retrocede / gira con steerHint y polar, luego retoma.
  3. Bug2 usa blocked + salida de M-line; Pure Pursuit frena con forwardClear bajo; VFH elige el sector más libre de polar; Custom lee lo que uses en loop().
  4. Recuperación: si casi no se mueve ~1.5–1.8 s → atrás → mira el bin polar más libre → escapa.

     ↓ no

5. Your own algorithms (Custom JS)

5. Tus propios algoritmos (Custom JS)

  1. Select Custom (JS) — the pad opens over the 3D view.
  2. Copy the read-only void setup API and paste it to an AI or notes.
  3. Write a loop() that assigns v and omega.
  4. Check → Save (stored in localStorage.customLoopJs).

Variables you can read

robotX, robotZ, heading, waypointX, waypointZ, waypointDist, headingErr, blocked, forwardClear, nearest, lidar, ultrasonic, ir, floorIr, MAX_SPEED, MAX_OMEGA, plus whitelisted Math and draw(x, z).

v = MAX_SPEED * 0.60
omega = headingErr * 2.00
draw(robotX, robotZ)

Forbidden: DOM, fetch, eval, new, objects, function/return. Only robot vars, math, and draw.

Want a new built-in algorithm?

Add a mode in nav.js (command function + registration), then a radio/button in index.html and i18n strings in main.js. Keep the portable layout — avoid splitting into many micro-modules unless you need to.

Want a new sensor?

Extend sensorConfig + UI checkbox in main.js/index.html, implement the reading in SensorSuite (nav.js), and expose the value to Custom via the Custom setup text / loop wrapper in main.js.

  1. Elige Custom (JS) — se abre el pad sobre la vista 3D.
  2. Copia el API de void setup (solo lectura) y pégalo a una IA o a tus notas.
  3. Escribe un loop() que asigne v y omega.
  4. Checar → Guardar (queda en localStorage.customLoopJs).

Variables de lectura

robotX, robotZ, heading, waypointX, waypointZ, waypointDist, headingErr, blocked, forwardClear, nearest, lidar, ultrasonic, ir, floorIr, MAX_SPEED, MAX_OMEGA, más Math permitido y draw(x, z).

v = MAX_SPEED * 0.60
omega = headingErr * 2.00
draw(robotX, robotZ)

Prohibido: DOM, fetch, eval, new, objetos, function/return. Solo vars del robot, matemáticas y draw.

¿Quieres un algoritmo built-in nuevo?

Agrégalo en nav.js (función + registro), botón en index.html e i18n en main.js. Mantén el diseño portable — no lo partas en muchos micromódulos si no hace falta.

¿Quieres un sensor nuevo?

Extiende sensorConfig + checkbox en main.js/index.html, implementa la lectura en SensorSuite (nav.js) y expón el valor al Custom en el texto de setup / wrapper del loop en main.js.

7. FAQ

7. Preguntas frecuentes

Why doesn’t the rover avoid the hole? ¿Por qué el rover no evita el hoyo?

Floor IR defaults off so it can drive into depressions like a 4×4. Turn Floor IR on to treat hole edges as obstacles.

IR de piso viene apagado para que entre a depresiones como un 4×4. Actívalo para tratar los bordes del hoyo como obstáculos.

Does the rover tilt on uneven terrain? ¿El rover se inclina en terreno irregular?

Yes. The chassis follows the ground under each of the four wheels (pitch / roll).

Sí. El chasis sigue el suelo bajo cada una de las cuatro ruedas (pitch / roll).

How do I see the log or debug a stuck run? ¿Cómo veo el log o depurar una corrida atascada?

Open Error Report on the left panel. It includes robot state, the recent log, and Copy / JSON / CSV.

Abre Reporte de error en el panel izquierdo. Incluye estado del robot, el log reciente y Copiar / JSON / CSV.

How do I save / load a map? ¿Cómo guardo / cargo un mapa?

Save map stores a dated entry in the browser. Load map opens a picker with timestamps and counts (waypoints / props / terrain).

Guardar mapa guarda una entrada con fecha. Cargar mapa abre un selector con timestamps y conteos (waypoints / props / terreno).

How do I try my own algorithm? ¿Cómo pruebo mi propio algoritmo?

Select Custom (JS), copy the setup API, write a loop() that sets v and omega, then Check → Save. See §5.

Elige Custom (JS), copia el API de setup, escribe un loop() que asigne v y omega, luego Checar → Guardar. Ver §5.
